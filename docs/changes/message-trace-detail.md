### Added
- **BCP "Nachrichtenablaufverfolgung": detail panel.** Clicking a message (or Enter on its row) opens a side panel (EditPanel, full screen below 768 px) with three tabs: *Übersicht* (direction inbound / outbound / internal, Message-ID, sender, recipients, subject, size, status, time, related entries of the same message: acceptance, delivery attempts, other recipients), *Verarbeitung auf CoreMail* (timeline of the recorded stages with time, duration, result badge and details) and *Zustellweg (Hops)* (Received chain of the stored original, oldest hop first, with delays, TLS and an Authentication-Results / ARC summary; outbound: CoreMail → each MX host the queue connected to). Entries written before 10.2 say "Für ältere Nachrichten sind weniger Details gespeichert."
- **Message trace stages (`metadata.trace`).** The smtp-server MAIL_FLOW rows now record what CoreMail did, from data the path computes anyway: inbound connection (client IP, HELO, port, protocol, TLS version + cipher), connect-stage checks (DNSBL/DNSWL, GeoIP), RCPT checks (sender lists, greylisting), SPF / DKIM / DMARC / ARC with domains, sender lists, attachment filter, ClamAV, rspamd score + verdict, content-filter verdict, alias expansion, transport rules, inbox rules, admin forwarding, delivery (mailbox + folder, rejection reply, quarantine); SMTP submission (AUTH user, queue tracking ids); queue attempts (job id, attempt, DKIM domain + selector, MX records as resolved, connected host + IP, STARTTLS, remote reply code + text, DSNs, deferred / final result). Bounded (48 stages, capped strings and lists), no message content. Shared recorder / sanitiser / Authentication-Results parser in `@coremail/storage` (`message-trace.ts`).
- security-filter `/check/content` answers carry an additive `checks` summary (auth, sender lists, attachments, ClamAV, rspamd, per-stage durations); smtp-server validates it field by field.
- Admin API `GET /api/v1/admin/message-trace/:id` (area `compliance`): the entry, its validated trace (transport rule ids resolved to names), related entries (queue tracking id / Message-ID within −2 / +8 days) and the delivery path. An entry outside the admin's scope answers 404 like an unknown id; related entries are scope-filtered; the stored original is only read from a mailbox of the scope's domains (header block only, first 64 KB); addresses of other hosted domains are redacted in the whole answer.

No schema change (the trace lives in the existing `SystemLog.metadata` JSON); no breaking change.
