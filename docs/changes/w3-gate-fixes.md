### Fixed
- Upgrade to 9.5 no longer stops at the schema check: the new `tasks` unique constraint on (userId, uid) covers the new optional column `uid`. schema-sync's duplicate check could not read that column on a 9.4.0 (or older) database, so it refused the update. Now a guard query runs first. When the table does not exist yet, or an optional constraint column without a default does not exist yet, schema-sync skips the check: the column is NULL in every row, and NULLs never conflict. schema-sync reads which columns are optional from the target `schema.prisma` (`COREMAIL_PRISMA_SCHEMA_FILE`, default `prisma/schema.prisma` in the storage package). Real query errors, unreadable schemas and missing columns with a default still fail closed. The e2e step `schema-upgrade` also upgrades a 9.4.0 database holding two tasks of one user.
- MAPI: the default folders always carry the names Outlook expects (Inbox, Drafts, Sent Items, Deleted Items, Junk Email, Archive). Before, the name came from the folder row, which depends on how the mailbox was created. The admin API stores "Sent Items", the setup wizard stores "Gesendet", and older or restored rows store the IMAP name. Outlook showed whichever one the row held. Mailboxes created by the setup wizard see their default folders renamed once in Outlook.
- e2e runner: the results file is `results-all.json` for a full run. A long selection of steps gets `results-<n>-steps-<hash>.json`. Before, the file name joined every step name, which exceeded the Windows path limit and crashed the runner at the end. The `mapi` step checks the default folders by their Outlook names directly below Top of Information Store. Its Outbox submit check logs on by itself, so it no longer fails as a follow-on error.

No API or protocol change, no schema change (SemVer: PATCH).
