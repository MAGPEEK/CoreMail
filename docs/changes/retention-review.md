### Fixed
- Retention (Managed Folder Assistant): items a policy moved to "Recoverable Items/Deletions" ("Löschen (wiederherstellbar)") stay recoverable for `DELETED_ITEM_RETENTION_DAYS` (default 30, `0` = until purged by hand) — the window "Gelöschte Elemente wiederherstellen" shows. They were removed after 14 days (undocumented `RETENTION_DELETIONS_TTL_DAYS`, no longer read).
- Retention: when several policies apply to one mailbox, the DPT and the RPT of each folder now come from the most specific assignment (user before domain before "Alle Postfächer"), then the longest retention period. Before, the policy the database returned first won, so a global "Junk 14 Tage endgültig löschen" could override a user's longer policy.
- Retention: a legacy policy without tags (pre-3.11 fields `retentionDays` / `action` / `scope`) keeps its scope. A "Junk" or "Posteingang" policy acted on every folder of the mailbox; `MOVE_TO_FOLDER` moves to its `targetFolder` instead of the Archive.
- Retention: subfolders inherit the tag of their parent (personal folder tag, or the RPT of the default folder above them — webmail subfolders and IMAP "INBOX.x" folders). Only top-level default folders count as Inbox/Junk/…: a subfolder named "Spam" below the Inbox no longer gets the Junk tag.
- Retention: "In Archiv verschieben" leaves items in the Archive folder and its subfolders where they are (an archive subfolder was flattened into "Archive").
- Retention: "Nur markieren" sets `retentionExpiresAt` once instead of writing the item every run (a new modSeq per item and day, re-synced by IMAP/ActiveSync clients), and no longer stores the DPT/RPT as the item's own tag — which then outranked later policy changes. Such item tags from earlier runs are ignored; only personal tags count on an item.
- Retention: personal tags a user put on a folder or item in the webmail apply even when no policy is assigned to the mailbox.
- Retention: policies assigned to "Alle Postfächer" or a domain also reach the shared mailboxes (of that domain).
- Retention: permanently deleted items are removed through the message store (expunge) and the deleted-items purge (ActiveSync item state, unreferenced raw/attachment objects); the stored quota counter is no longer reduced twice; "Recoverable Items/Purges" of shared mailboxes is emptied too. The run result counts a permanently deleted item once.
- Retention: folder counters are recomputed after a run moved items; the "Recoverable Items" folders are created only in mailboxes where something is soft-deleted; one failing mailbox (also in the recoverable-items sweep) no longer stops the others; a run stops when it loses its cluster lock; large folders are read in pages and written in batches.

No API path, schema or configuration change (one undocumented environment variable is no longer read, see above). Behaviour changes that remove more mail than before on the first run after the update: expired items in shared mailboxes covered by a global or domain policy, items in folders with a personal tag of users without a policy, and items in subfolders of default folders with an RPT.
