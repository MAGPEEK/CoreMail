# CoreMail v5.7.1 — JMAP server, MAPI over HTTP optional, build hardening

> Release notes for tag `v5.7.1` (merge commit `8d82a71`). Image: `magpeek/coremail-app:5.7.1`.

## Highlights

**JMAP has arrived.** In addition to IMAP4rev2, SMTP submission, POP3,
EWS, CalDAV/CardDAV and ActiveSync, CoreMail now speaks the **JSON Meta Application Protocol** — the
IETF standard for mailbox access over HTTPS/JSON (RFC 8620/8621). JMAP-capable clients
set up an account using only the email address: discovery via
`https://<host>/.well-known/jmap`, login with password or app password, push without
polling via Server-Sent Events or WebSocket.

**MAPI over HTTP is back — as a switch.** The Outlook Exchange stack removed in v5.4.0
is back in the code, **off** by default, and can be enabled in the BCP under
*Server → MAPI over HTTP* without a restart. Outlook 2013–2021 connect with it
as a native Exchange account; Outlook 2024 LTSC / M365 Classic stay on the IMAP path
(Microsoft enforces Modern Auth against Entra/ADFS there).

## JMAP in detail

| RFC | Scope |
|-----|--------|
| **8620** Core | Session, method calls with result references, `Core/echo`, blob upload/download, EventSource push, `PushSubscription` with verification |
| **8621** Mail | `Mailbox`, `Email` (get/changes/query/set/copy/import/parse), `Thread`, `Identity`, `EmailSubmission` (delayed sending + cancellation), `SearchSnippet`, `VacationResponse` |
| **8887** WebSocket | `wss://<host>/jmap/ws`, subprotocol `jmap`, push via `StateChange` |
| **9404** Blob | `Blob/upload`, `Blob/get` (text/Base64/digest), `Blob/lookup` |
| **9425** Quota | Storage quota per account |
| **9670** Sharing | `Principal` (users, Shared Mailboxes), `ShareNotification` |
| **9749** VAPID | `applicationServerKey` for Web Push in the session |

- **Accounts**: own mailbox, Shared Mailboxes (FULL_ACCESS / READ_ONLY) and
  delegated mailboxes appear as separate JMAP accounts.
- **Auth**: Basic (password; with MFA only app password; LDAP/OIDC via auth-service) or
  Bearer (session JWT, also `?access_token=` for EventSource/WebSocket).
- **Live sync with the webmail**: JMAP writes and SMTP inbound deliveries go through
  the same Redis channel — MWA and JMAP clients see each other's changes immediately.
- **Switch**: BCP → Server → "JMAP" (default on). Off → `/jmap/*` returns 404.
- Docs: [`docs/jmap.md`](../jmap.md)

## MAPI over HTTP (v5.7.0)

- Restored from v5.2 (`packages/ews-server/src/mapi/`), behind
  `ServerSettings.mapiHttpEnabled` (default **off**); 404 on `/mapi/*` while off.
- Autodiscover returns the `mapiHttp` block only when the switch is on.
- ADFS emulation (v5.3.0) remains removed.

## Build & operations

- pnpm pinned to **11** (`packageManager`, Dockerfiles) — `pnpm@latest` pulled pnpm 12 and
  broke the install.
- 70 stale checked-in `src/**/*.js` artifacts removed, `noEmit` in the
  frontend tsconfigs.
- New service image `coremail-jmap-server` in the CI matrix; PR runs build only
  `linux/amd64` (timeout 45 min), `main`/tags still amd64 + arm64.
- New internal port **3006** (jmap-server), new environment variables
  `JMAP_PORT`, `JMAP_SERVICE_URL` (set in `docker-compose*.yml`).

## Upgrade notes

- Schema extensions are **non-destructive** (`prisma db push` at startup):
  `server_settings.mapiHttpEnabled` (false), `server_settings.jmapEnabled` (true),
  `messages.threadId`, new table `jmap_push_subscriptions`.
- Behavior after the upgrade: IMAP/SMTP/EWS/DAV/EAS unchanged; JMAP active immediately;
  MAPI off until enabled in the BCP.
- Reverse proxy in front of CoreMail: pass WebSocket upgrades through for `/jmap/ws`
  (`Upgrade`/`Connection` headers). The integrated TLS proxy already does this.
- Optional DNS record: `_jmap._tcp.<domain>. SRV 0 1 443 mail.<domain>.`

## Known limitations (JMAP)

- `*/queryChanges` → `cannotCalculateChanges` (client reloads); no tombstones for
  deleted messages.
- An email lives in exactly one folder (`maxMailboxesPerEmail: 1`).
- Filters `header`, `*InThreadHaveKeyword` and sorting by `to` are not supported.
- `bodyStructure` is synthesized from the stored fields.
- Calendars/contacts via JMAP (JSCalendar/JSContact) are not included — CalDAV/CardDAV
  remain responsible.
