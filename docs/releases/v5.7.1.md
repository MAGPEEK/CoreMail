# CoreMail v5.7.1 — JMAP-Server, MAPI over HTTP optional, Build-Härtung

> Release-Notes zum Tag `v5.7.1` (Merge-Commit `8d82a71`). Image: `magpeek/coremail-app:5.7.1`.

## Highlights

**JMAP ist da.** CoreMail spricht jetzt zusätzlich zu IMAP4rev2, SMTP-Submission, POP3,
EWS, CalDAV/CardDAV und ActiveSync das **JSON Meta Application Protocol** — den
IETF-Standard für Postfachzugriff über HTTPS/JSON (RFC 8620/8621). JMAP-fähige Clients
richten ein Konto allein über die E-Mail-Adresse ein: Discovery über
`https://<host>/.well-known/jmap`, Login mit Passwort oder App-Passwort, Push ohne
Polling über Server-Sent Events oder WebSocket.

**MAPI over HTTP ist zurück — als Schalter.** Der in v5.4.0 entfernte Outlook-Exchange-
Stack liegt wieder im Code, standardmäßig **aus**, und lässt sich im BCP unter
*Server → MAPI over HTTP* ohne Neustart zuschalten. Outlook 2013–2021 verbinden sich
damit als natives Exchange-Konto; Outlook 2024 LTSC / M365 Classic bleiben beim IMAP-Weg
(Microsoft erzwingt dort Modern Auth gegen Entra/ADFS).

## JMAP im Detail

| RFC | Umfang |
|-----|--------|
| **8620** Core | Session, Method-Calls mit Result-References, `Core/echo`, Blob-Up-/Download, EventSource-Push, `PushSubscription` mit Verifikation |
| **8621** Mail | `Mailbox`, `Email` (get/changes/query/set/copy/import/parse), `Thread`, `Identity`, `EmailSubmission` (verzögertes Senden + Abbruch), `SearchSnippet`, `VacationResponse` |
| **8887** WebSocket | `wss://<host>/jmap/ws`, Subprotokoll `jmap`, Push per `StateChange` |
| **9404** Blob | `Blob/upload`, `Blob/get` (Text/Base64/Digest), `Blob/lookup` |
| **9425** Quota | Speicherkontingent pro Account |
| **9670** Sharing | `Principal` (User, Shared Mailboxes), `ShareNotification` |
| **9749** VAPID | `applicationServerKey` für Web Push in der Session |

- **Accounts**: eigenes Postfach, Shared Mailboxes (FULL_ACCESS / READ_ONLY) und
  delegierte Postfächer erscheinen als getrennte JMAP-Accounts.
- **Auth**: Basic (Passwort; bei MFA nur App-Passwort; LDAP/OIDC über auth-service) oder
  Bearer (Session-JWT, auch `?access_token=` für EventSource/WebSocket).
- **Live-Sync mit dem Webmail**: JMAP-Schreibzugriffe und SMTP-Eingänge laufen über
  denselben Redis-Kanal — MWA und JMAP-Clients sehen Änderungen gegenseitig sofort.
- **Schalter**: BCP → Server → „JMAP“ (Standard an). Aus → `/jmap/*` liefert 404.
- Doku: [`docs/jmap.md`](../jmap.md)

## MAPI over HTTP (v5.7.0)

- Wiederhergestellt aus v5.2 (`packages/ews-server/src/mapi/`), hinter
  `ServerSettings.mapiHttpEnabled` (Default **aus**); 404 auf `/mapi/*`, solange aus.
- Autodiscover liefert den `mapiHttp`-Block nur bei aktivem Schalter.
- ADFS-Emulation (v5.3.0) bleibt entfernt.

## Build & Betrieb

- pnpm auf **11** gepinnt (`packageManager`, Dockerfiles) — `pnpm@latest` zog pnpm 12 und
  brach den Install.
- 70 veraltete eingecheckte `src/**/*.js`-Artefakte entfernt, `noEmit` in den
  Frontend-tsconfigs.
- Neues Service-Image `coremail-jmap-server` in der CI-Matrix; PR-Läufe bauen nur
  `linux/amd64` (Timeout 45 min), `main`/Tags weiter amd64 + arm64.
- Neuer interner Port **3006** (jmap-server), neue Umgebungsvariablen
  `JMAP_PORT`, `JMAP_SERVICE_URL` (in `docker-compose*.yml` gesetzt).

## Upgrade-Hinweise

- Schema-Erweiterungen sind **nicht destruktiv** (`prisma db push` beim Start):
  `server_settings.mapiHttpEnabled` (false), `server_settings.jmapEnabled` (true),
  `messages.threadId`, neue Tabelle `jmap_push_subscriptions`.
- Verhalten nach dem Upgrade: IMAP/SMTP/EWS/DAV/EAS unverändert; JMAP sofort aktiv;
  MAPI aus, bis es im BCP eingeschaltet wird.
- Reverse Proxy vor CoreMail: für `/jmap/ws` WebSocket-Upgrades durchreichen
  (`Upgrade`/`Connection`-Header). Der integrierte TLS-Proxy tut das bereits.
- Optionaler DNS-Eintrag: `_jmap._tcp.<domain>. SRV 0 1 443 mail.<domain>.`

## Bekannte Grenzen (JMAP)

- `*/queryChanges` → `cannotCalculateChanges` (Client lädt neu); keine Tombstones für
  gelöschte Nachrichten.
- Eine E-Mail liegt in genau einem Ordner (`maxMailboxesPerEmail: 1`).
- Filter `header`, `*InThreadHaveKeyword` und Sortierung nach `to` nicht unterstützt.
- `bodyStructure` wird aus den gespeicherten Feldern synthetisiert.
- Kalender/Kontakte per JMAP (JSCalendar/JSContact) sind nicht enthalten — CalDAV/CardDAV
  bleiben zuständig.
