# CoreMail v9.0.0 — OWASP security hardening, mailbox and transport upgrades, encrypted backups

**Image:** `magpeek/coremail-app:9.0.0` · **Helm chart:** 2.0.0 · **Date:** 2026-11-15 · **Predecessor:** v8.0.0

## Highlights

CoreMail was audited against OWASP Top 10 2021 / ASVS 4.0.3 L2 in four areas:
- API and authentication
- webmail and admin frontends
- mail protocols
- supply chain and deployment

Every finding was fixed with regression tests. Transport, mailbox, admin and webmail logic was extended for CoreMail's single-host design. Two independent review rounds followed, and all their findings were fixed too.

Verification:
- `pnpm -r test`: 1,894 tests
- end to end against the real image in both storage modes (MinIO 135/135, filesystem 130/130), including an upgrade from an 8.0.0 database
- `pnpm audit --prod`: 0 critical and 1 high left (not reachable), down from 2 critical and 74 high

- **Security:**
  - shared login lockout for web and mail
  - HttpOnly refresh cookies, no tokens in URLs, SSE tickets, re-auth for app passwords
  - real SPF/DKIM/DMARC enforcement with local-domain anti-spoofing
  - ReDoS-safe rule regexes and pre-auth DoS limits
  - SSRF guards, HMAC-signed audit exports, encrypted backups
  - fail-closed schema sync, hardened containers, signed CI images
- **SMTP:** CHUNKING/BINARYMIME, DSN (RFC 3461), SMTPUTF8, HELP. Outbound retries for 48 h with a delay DSN after 4 h.
- **IMAP:** QRESYNC, SORT/THREAD, ACL (read-only), COMPRESS=DEFLATE.
- **Mailbox:**
  - Quota levels: warning mail, prohibit send, prohibit send/receive
  - recover deleted items for 30 days
  - out-of-office replies once per sender and period
  - server drafts with autosave and undo send that survives closing the tab
- **Webmail:** keyboard shortcuts (CoreMail and Gmail-compatible sets), undo for delete/move, search operators, quota bar, accessible dialogs.
- **Admin panel:** one permission map for API and UI (`/admin/me/permissions`), read-only views, a shared list pattern with a mailbox detail panel, "Sign out everywhere", last login.
- **Client setup:** Thunderbird autoconfig, Apple configuration profile, and recommended SRV records in the DNS check ([docs/clients.md](../clients.md)).
- **Deployment:** Docker Compose variants `minimal` / `standard` / `full`, a storage mounting guide ([docs/docker-compose.md](../docker-compose.md)), and Helm chart 2.0.0.

## Breaking changes — read before upgrading

The full list is in [CHANGELOG.md](../../CHANGELOG.md) → 9.0.0 → "Upgrade notes (breaking)".

1. **Deleted items.** Messages deleted more than 30 days ago are purged on the first start, together with their stored objects. To keep them, set `DELETED_ITEM_RETENTION_DAYS=0` before upgrading.
2. **Quotas.** Quotas are enforced:
   - A mailbox above 87 % of its quota cannot send.
   - A full mailbox rejects mail with `552 5.2.2`. Set `QUOTA_FULL_PERMANENT=false` to answer 452 instead.
   - Users above 83 % get one warning mail.
3. **Spoofing protection.**
   - Mail failing the sender's DMARC `p=reject` is rejected.
   - Mail using your own domains without alignment goes to Junk, or is rejected if your domain publishes `p=reject`. Allow third-party senders with `LOCAL_SPOOF_ALLOW`.
   - Unauthenticated mail with zero or several From addresses is rejected.
4. **Lockout and connection limits.** Private/NAT addresses now count toward the lockout and connection limits. Behind NAT or a reverse proxy, set `MAIL_AUTH_EXEMPT_CIDRS` / `MAIL_CONN_EXEMPT_CIDRS`. IMAP allows 50 connections per IP and 20 per user.
5. **API clients.**
   - `?token=` is not accepted any more; use the Authorization header (SSE: `?ticket=`).
   - Re-auth errors return 403.
   - `DELETE /auth/sessions/admin/:userId` returns 410; use `POST /api/v1/admin/mailboxes/:id/revoke-sessions`.
   - Creating an app password needs `currentPassword` or `mfaCode`.
   - Audit export signatures are `hmac-sha256=`.
6. **Rules.** Regex rules with backreferences, lookarounds or named groups no longer match. The limit is 20 regex conditions per user.
7. **Roles.** SERVER_MANAGEMENT no longer gets mailbox data (backups, downloads, import); COMPLIANCE_MANAGEMENT does.
8. **Compose.**
   - New settings: `RSPAMD_CONTROLLER_PASSWORD` and `BACKUP_ENCRYPTION_KEY`. Keep a copy of the backup key off the server.
   - rspamd moves to the network `10.253.253.0/29` (`RSPAMD_NET_PREFIX`).
   - The app container drops capabilities.
   - MinIO/S3 credentials have no defaults any more.
9. **Schema sync.** Destructive schema changes now stop the start until `COREMAIL_ALLOW_SCHEMA_DATA_LOSS=true` is set; a `pg_dump` is written first. All schema changes in this release are applied automatically.
10. **HTTPS redirect.** When the integrated HTTPS proxy is active, HTTP is redirected to HTTPS. Behind a TLS terminator without forwarding headers, set `HTTP_REDIRECT_HTTPS=false`.
11. **Helm 2.0.0.** `app.mailAuth.limitPrivateIps` makes rendering fail; use `exemptCidrs`.

## Upgrade (Docker Compose)

```bash
cd /opt/coremail
docker compose exec postgres pg_dump -U coremail coremail | gzip > coremail-pre-9.sql.gz
git pull                                  # new compose files, .env.example
bash scripts/setup.sh                     # appends missing keys (RSPAMD_CONTROLLER_PASSWORD, BACKUP_ENCRYPTION_KEY) to .env
docker compose pull && docker compose up -d
```

- Users sign in to the webmail once again, because sessions move to the HttpOnly cookie.
- On Synology, re-run `scripts/synology-setup.sh`: it pins the legacy backup key and updates the rspamd controller config.

## Known limitations

- **Shared/delegated mailboxes over IMAP:** they are not in the IMAP namespace, so ACL only covers the user's own folders.
- **THREAD=REFERENCES:** it uses In-Reply-To and Message-ID; the full References header is not stored.
- **Restore UI:** shared mailboxes have no restore view for deleted items.
- **Unreachable advisory:** `decode-uri-component` (via MinIO's query-string) has an advisory, but the vulnerable path is not used.
- **Helm chart:** it has not been tested on a real cluster yet (lint, template, kubeconform only).
