# CoreMail v9.5.0: ActiveSync calendar, tasks, notes and contacts, CalDAV tasks, folder permissions, domain-scoped admins, MAPI cached mode, profile photo

**Image:** `magpeek/coremail-app:9.5.0` · **Helm chart:** 2.3.0 · **Date:** 2026-11-19 · **Predecessor:** v9.4.0

This is a minor release: you can upgrade from 9.4.0 without changing your configuration. The schema changes are additive and are applied automatically at start. Independent reviews covered every work package; every finding was fixed with a regression test. Please read the behaviour changes below before you upgrade.

## Highlights

- **ActiveSync calendar, tasks, notes and contacts.** Phones (iOS, Android and other ActiveSync apps) sync the own calendars, the task list, notes and contacts both ways — time zones, recurring meetings with exceptions, attendees, reminders, rooms booked with the same rules as the webmail, contact pictures; values a phone has no slot for stay on the server. Existing phones pick up the new folders by themselves. [docs/activesync.md](../activesync.md)
- **CalDAV task list.** Every user has a task list "Aufgaben" that Apple Reminders, Thunderbird and DAVx⁵ (jtx Board, Tasks.org) sync both ways with the webmail tasks. [docs/caldav.md](../caldav.md)
- **Contacts with several values and contact groups.** Several e-mail addresses, phone numbers, postal addresses, web pages and chat addresses per contact, structured name, birthday and anniversary, categories; contact groups ("Kontaktlisten") with "E-Mail an Liste", also over CardDAV. Notes get categories. [docs/contacts.md](../contacts.md)
- **Folder permissions** ("Berechtigungen"): roles from Besitzer to Prüfer per folder and user or "Standard", in the webmail, the BCP, the REST API and as real IMAP ACLs. [docs/mailbox-management.md](../mailbox-management.md)
- **Domain-scoped admin roles.** Help desk, recipient, compliance, hygiene and view-only admins can be limited to one or more domains; they see only their domains and no addresses of other domains. CLI `coremail role`. [docs/rbac.md](../rbac.md)
- **MAPI cached mode.** MAPI over HTTP now supports cached mode (incremental synchronization, offline changes uploaded, IDs the client assigned kept, conflict detection) — desktop clients no longer need cached mode switched off. [docs/mapi.md](../mapi.md)
- **Profile photos** with a crop dialog, shown for internal users in the message list, reading pane, contacts and meeting attendees; policy switch `profilePhoto`.
- **Rooms answer mailed invitations** with an iMIP reply (accepted / declined with the reason / tentative); recurring room invitations are checked occurrence by occurrence.
- **Webmail accessibility and phones.** ARIA tree and grid with arrow-key navigation, skip link; a single-pane layout below 768 px and a folder drawer up to 1099 px.
- **BCP.** Editing users, shared mailboxes and domains opens in a side panel with tabs; international domains are shown in Unicode with mixed-script warnings.
- **Data.** Backups contain contact groups and the received date of every message; restore brings back contacts and contact groups and keeps the original received date (restored mail gets a 30-day retention grace).
- **Security.** DMARC alignment follows the Public Suffix List everywhere it is used; no address or folder-name oracles in folder permissions and IMAP ACL.

## Upgrade

```bash
cd /opt/coremail && git pull && docker compose pull && docker compose up -d
```

- **Schema:** additive, applied automatically (new tables `folder_permissions`, `admin_scopes`, `contact_groups`, `mapi_objects`, new nullable or defaulted columns). The new unique constraint `tasks (userId, uid)` lies on a column that is new in 9.5, so schema-sync applies it without a duplicate check (the e2e step `schema-upgrade` upgrades a 9.4.0 database).
- **Contacts backfill:** after the first start the structured columns of existing contacts are filled once in the background (resumable; sync clients see no change).
- **ActiveSync:** existing phones get Ping Status 7 once and then see the Calendar, Tasks, Notes and Contacts folders (when the webmail modules are on). No new account setup is needed.
- **MAPI:** the default folders now always carry the names MAPI clients expect (Inbox, Sent Items, Deleted Items …); mailboxes created by the setup wizard see their default folders renamed once in the desktop client. An address-book bind with CP_WINUNICODE is refused (`InvalidCodepage`); desktop clients bind with their ANSI code page.
- **Rooms reply by default:** resource mailboxes now send iMIP replies to organizers who invite them by mail (`sendReplies`, on by default; switch it off per resource in the admin API).
- **Notes:** REST refuses `color` values other than `YELLOW BLUE GREEN PINK PURPLE` with 400 (a colour a note already has stays accepted).
- **DMARC alignment:** sibling subdomains of one organization are now aligned (`bounces.example.com` ~ `mail.example.com`); a domain across a public suffix no longer vouches for its parent.
- **IMAP ACL:** SETACL / DELETEACL on own folders now set folder permissions instead of answering `NO [NOPERM]`.
- **Admin scopes:** organisation-wide admins work as before. A domain that still scopes an admin cannot be deleted (409 `DOMAIN_SCOPES_ADMINS`).
- **New optional settings:** `PROFILE_PHOTO_UPLOAD_LIMIT`, `PROFILE_PHOTO_UPLOAD_WINDOW_SEC`.

## Known limitations

- **MAPI cached mode** has not been tested with a real desktop client yet (protocol tests and the e2e client only). Hierarchy changes have no conflict detection (the last change wins); message conflicts are resolved for the server version; a flag cleared by another client (`\Answered`, `$Forwarded`, `\Draft`) keeps its old icon in the desktop client until the message changes otherwise; no folder associated information, no RTF bodies, no FastTransfer copy ROPs; changes of received messages other than the read state are not uploaded. Calendar and contacts over MAPI and NTLM are still not supported.
- **ActiveSync PIM:** the item version is `updatedAt` in milliseconds — two changes of one item within the same millisecond reach a phone as one; recurrence rules without an ActiveSync form (several month days, hourly) are not sent and are kept on device edits; device writes send no meeting invitations (the phone sends them); shared calendars and contact groups are not synced.
- **Folder permissions:** where a grantee may create or rename folders, a refused create still differs from a successful one, so names of hidden sibling folders can be guessed one by one; JMAP and MAPI only know mailbox-level grants.
- **Domain-scoped admins:** the mail-flow settings of an in-scope mailbox are shown as stored (not redacted); display names in separate audit fields are not redacted; per-mailbox backups stay organisation-wide; `GET /api/v1/user/me` `adminAreas` is not scope-aware (the API enforces anyway).
- **Profile photos** are not exposed over CardDAV, ActiveSync or MAPI.
- Spanish and Italian webmail show English texts for the newer screens.
