# CoreMail v9.5.1: MAPI HTTPS warning fix

**Image:** `magpeek/coremail-app:9.5.1` · **Helm chart:** 2.3.1 · **Date:** 2026-11-19 · **Predecessor:** v9.5.0

A patch release. Upgrade from 9.5.0 without configuration changes; no schema change.

## Fixed

- **BCP → Protokolle & Dienste** no longer shows the false warning "MAPI über HTTP ist eingeschaltet, aber HTTPS (Port 443) ist nicht aktiv oder hat kein vertrauenswürdiges Zertifikat" when port 443 serves a valid certificate for the public host name. The overview looked only at the certificate marked "HTTPS aktiv", while the integrated HTTPS server serves every valid certificate by SNI. It now checks the certificate the HTTPS server actually serves for the public host name (one shared selection for the overview and the TLS proxy). The warning stays when no certificate covers the host name or the served one is self-signed, a Let's Encrypt staging certificate or expired.

## Changed

- **HTTPS card:** an always visible status line says whether HTTPS is active and with which TLS versions ("HTTPS ist aktiv mit TLS 1.2 und 1.3 — für Webmail, ActiveSync, MAPI usw. ist kein weiterer Schalter nötig.").
- **Legacy TLS switch** (HTTPS and mail ports) is labelled "Zusätzlich veraltete TLS-Versionen 1.0/1.1 zulassen (optional)", with a hint that modern clients do not need it; while it is on, the warning starts with "Optionaler Kompatibilitätsmodus aktiv:". The old label read like the switch that turns HTTPS on.
