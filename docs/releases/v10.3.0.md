# CoreMail v10.3.0: admin MCP interface, branding page, neutral wording

**Image:** `magpeek/coremail-app:10.3.0` · **Helm chart:** 3.3.0 · **Date:** 2026-11-20 · **Predecessor:** v10.2.0

A minor release: upgrade from 10.2.0 without configuration changes; additive schema changes only.

## Highlights

- **Admin MCP interface.** Administrators can manage CoreMail with any MCP client. Switch it on under BCP → Infrastruktur → "KI-Schnittstelle (MCP)" (off by default), create a personal token (read only, or read and write) and paste the shown configuration into the client. Every tool runs with the admin's own role and domain scope, every call is in the audit log, and mailboxes or domains cannot be deleted through it. See [docs/mcp.md](../mcp.md).
- **Branding page reworked.** One logo upload — the favicon is generated from it; own dark-mode logo and favicon are optional under "Erweitert". Images apply together with the other settings via the save bar at the bottom; the preview switches between webmail and login page, light and dark.
- **Clearer TLS card.** "Veraltete TLS-Versionen 1.0/1.1" with the switch in the card header.
- **Neutral wording.** Texts and documentation describe CoreMail on its own terms; protocol names stay.
- **New README** with quick start for minimal and maximal setups, with Docker Compose or plain `docker run`.

## Upgrade

```bash
cd /opt/coremail && git pull && docker compose pull && docker compose up -d
```

- The MCP interface stays off until you switch it on. If you run several CoreMail replicas behind a load balancer, route `/mcp` sticky.
