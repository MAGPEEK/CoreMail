# CoreMail v5.8.0 — Admin CLI `coremail`, new Docker Compose, EWS tied to MAPI

> Shipped together with v5.9.0 (English-only repository); the image tag is 5.9.0.

**Image:** `magpeek/coremail-app:5.9.0` · **Date:** 2026-10-28 · **Predecessor:** v5.7.1 (JMAP server)

## Highlights

### ⌨️ Admin CLI `coremail`

The app image now ships a command line for day-to-day administration — no browser needed, scriptable, with `--json`:

```bash
alias coremail='docker exec -it coremail coremail'
coremail login -u admin@example.com
coremail user create john@example.com --name "John Doe" --quota 10GB
coremail shared grant team@example.com john@example.com FULL_ACCESS SEND_AS
coremail connector disable pop3
coremail smtp banner set "mail.example.com ESMTP"
coremail cert letsencrypt --domains mail.example.com --email admin@example.com --services SMTP,IMAP,POP3
```

| Area | Functions |
|---------|-----------|
| Users | list, create (with mailbox), update, set password, delete |
| Mailboxes | usage/quota, folders with counters, set quota, recalculate usage |
| Shared Mailboxes | create, delete, grant/revoke permissions |
| Connectors | status of all services; SMTP/SMTP submission/IMAP/POP3 on/off, listener ports/address/TLS; toggle JMAP and MAPI/EWS |
| SMTP banner | show, set, reset |
| Certificates | list, self-signed, Let's Encrypt (HTTP-01), activate (HTTPS/protocols), renew, delete |

The CLI uses the REST admin API — the same roles and the same audit log as in the BCP. Login with password + TOTP, environment variables for scripts, or a ready-made token. Docs: [docs/cli.md](../cli.md).

### 🐳 New `docker-compose.yml`

Reduced to the essentials and explained throughout. Five required values from the `.env`, checked at startup:

```
JWT_SECRET · PEPPER · POSTGRES_PASSWORD · REDIS_PASSWORD · MINIO_ROOT_PASSWORD
```

If one is missing, `docker compose up` aborts immediately with a hint. `bash scripts/setup.sh` generates the `.env` with random values. Internal service URLs and ports are gone from the file (defaults in the image). Everything else — hostname, domains, certificates, connectors — is set up after startup in the BCP or via the CLI.

### 🔒 EWS only together with MAPI over HTTP

Exchange Web Services as a standalone Outlook path was obsolete: Outlook 2024 LTSC and Microsoft 365 do not speak Basic-Auth EWS against third-party servers. EWS remains as a companion protocol of MAPI over HTTP (free/busy, out of office, OAB) and is tied to the same switch: BCP → Server → **"MAPI over HTTP + EWS"** (default off). When it is off, `/EWS/*` and `/OAB/*` respond with 404 and Autodiscover does not advertise EWS. Outlook then sets itself up as an IMAP account.

## Upgrade

```bash
cd /opt/coremail && docker compose pull coremail && docker compose up -d coremail
```

- The existing `.env` remains valid. If you adopt the new Compose file: required values as above, everything else is optional.
- Outlook accounts that previously used EWS: enable "MAPI over HTTP + EWS" in the BCP or switch to IMAP.
- No schema change; no data loss.
