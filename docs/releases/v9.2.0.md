# CoreMail v9.2.0: accessible dark mode, every BCP function reviewed, ClamAV settings

**Image:** `magpeek/coremail-app:9.2.0` · **Helm chart:** 2.0.2 · **Date:** 2026-11-16 · **Predecessor:** v9.1.0

This is a minor release: you can upgrade from 9.1.0 without changing your configuration. A few settings that were saved but never applied now take effect — read the upgrade notes below. Two independent reviews covered the changes; every finding was fixed with a regression test.

**Verification:**
- `pnpm -r test`: 2,176 tests, 2,175 passed, 1 skipped, 0 failed.
- End to end against the real image: MinIO 135/135 and filesystem 130/130.
- Every BCP page was checked live against a running local stack (226 checks).

## Highlights

- **Dark mode that works everywhere (WCAG 2.2 AA).** Webmail and admin panel use semantic colour tokens for light and dark mode. Text reaches 4.5:1 and controls 3:1 in both themes, with all six accent colours. Keyboard focus is always visible, and reduced motion is respected. A test blocks raw colour classes from coming back.
- **Every BCP function reviewed.** Each admin page was checked for API contract, logic, permissions and leftovers, then fixed. Examples:
  - SMTP connection limits are now applied.
  - Queue retry, smarthost TLS test, message trace paging and partial settings saves work.
  - The last organisation admin can no longer be deleted or demoted.
  - "Unlimited" quota is really unlimited.
  - Backup schedules apply their retention, and parallel backups no longer overwrite each other.
- **ClamAV settings** in BCP → Protection → Antivirus:
  - Action on virus, scanner failure, timeout, scan size limit, and how heuristic, PUA and encrypted findings count.
  - Live engine and signature status, plus an EICAR self-test.
  - Mail that was not cleanly scanned carries `X-CoreMail-Virus-Scan`.
- **System information** shows the real release notes from the image instead of a hard-coded list.
- **Cleanup:**
  - MAPI-era Outlook setup box, Exchange mentions and RFC numbers removed from user-visible texts.
  - The Reports page with placeholder numbers is gone.

## Upgrade

```bash
cd /opt/coremail && git pull && docker compose pull && docker compose up -d
```

- **Schema:** six new `SecuritySettings` columns for ClamAV are added automatically, with no data loss.
- **Settings that now take effect** (check them once in the BCP):
  - **SMTP connection limits** apply to port 25 from public IPs. Submission (587/465) keeps only the per-IP limit, and private networks are exempt. An explicitly set `SMTP_MAX_CONNS_PER_IP` still wins. Failed AUTH attempts before disconnect follow the BCP value (default 5, previously a built-in 3).
  - **Listener addresses** (BCP → Services) are used for binding. A value that is not an IP address, or one that cannot be bound, falls back to all interfaces with a log message.
  - **Backup schedule retention** deletes a schedule's backups older than `retentionDays`. Only backups created after the upgrade are ever deleted, and the newest archive of every mailbox is always kept.
- **Behaviour changes:**
  - Mail that clamd refuses as too large follows the size policy (default: deliver marked `unscanned`) instead of the failure policy. If you defer mail on scanner failure, also set large mail to "Ablehnen" (reject).
  - Quarantined `VIRUS` messages can no longer be released.
  - Server settings validate host names. Correct a stored value that contains a port, an underscore or an IPv6 literal.
  - `POST /api/v1/admin/security/rspamd/learn/:type` answers `410 Gone`. It never trained rspamd; use the webmail's Junk / Not junk actions.

## Known limitations

- Remaining German-only strings in some admin pages are not yet translated.
- The clamd engine limits (`clamd.conf`) are shown as recommendations but must be set in the clamav container.
