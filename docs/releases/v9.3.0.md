# CoreMail v9.3.0: branding, working Let's Encrypt and mail certificates, shared mailboxes in the folder pane, backup restore

**Image:** `magpeek/coremail-app:9.3.0` · **Helm chart:** 2.1.0 · **Date:** 2026-11-17 · **Predecessor:** v9.2.0

This is a minor release: you can upgrade from 9.2.0 without changing your configuration. The schema changes are additive, and earlier API contracts are kept. Independent reviews covered every change; every finding was fixed with a regression test.

**Verification:**
- `pnpm -r test`: 2,462 tests, 0 failed (1 skipped; one test file, `certificates-admin.test.ts`, does not exit on its own when run alone — its tests pass).
- End to end against the real image: MinIO 166/166 and filesystem 153/153, including the new steps `tls`, `branding`, `backup` and `webmail`.
- On the test server: Let's Encrypt issuance, and all mail ports (993, 143, 465, 587, 995) serving the trusted certificate, checked from outside.

## Highlights

- **Branding.** BCP → Branding sets product name, colours, logos, favicon, login background, login text and footer links, with a live preview in light and dark mode. Contrast is checked, and the brand colour becomes the default accent. SVG logos are sanitised on the server and only ever shown through `<img>`.
- **Let's Encrypt works behind NAT.** Issuance no longer depends on the server reaching itself over its public address. Failures show the real reason (connection, DNS, CAA, rate limit …) with a „Retry" button. „Check prerequisites" tests DNS, CAA and port 80 beforehand, and staging can be used for tests.
- **Mail certificates apply on assignment.** Giving a certificate „Mail-Protokolle (SMTP · IMAP · POP3)" switches the mail servers to it immediately. Before, it took a second, separate action, and mail clients kept getting the self-signed certificate. Installations in that state are repaired at the next start. BCP → SSL/TLS shows which certificate each mail port really serves.
- **Shared and delegated mailboxes in the webmail folder pane.** They appear under „Freigegebene Postfächer" and open in the normal mail view: full width, resizable panes, reading pane setting, search, filters and bulk actions. Compose offers „Senden als" / „im Auftrag von".
- **Backup restore and automation.** Stored backups (encrypted or not) can be restored into the original or another mailbox, without duplicates on a second run. „Empfohlene Sicherung einrichten" creates a nightly full backup and a nightly system backup (encrypted `pg_dump`). Failed scheduled backups notify the admins.
- **Installations without rspamd or ClamAV.** When a scanner is switched off explicitly (minimal compose variant, Helm chart without it), its settings are hidden in the BCP and mail is not marked as unscanned. A stopped or missing scanner container counts as „unavailable", so the failure policy keeps applying.
- **DNS check** reports an MX record that points to an IP address or a CNAME.

## Upgrade

```bash
cd /opt/coremail && git pull && docker compose pull && docker compose up -d
```

- **Schema:** new tables and columns are added automatically, with no data loss (`branding`, `Certificate.acmeStaging`, `Certificate.lastErrorCode`, `UserSettings.hiddenSharedMailboxes`, ClamAV-related settings from 9.2 unchanged).
- **Certificates:** at the first start the gateway aligns which certificate SMTP/IMAP/POP3 use with what the BCP shows. If you had assigned a Let's Encrypt certificate to the mail services but never pressed the separate „use this certificate" button, the mail servers switch to it now. A self-signed default for `mail.localhost` is regenerated for your public host name.
- **Behaviour changes:**
  - Deleting a non-empty folder (own mailbox with `?force=true`, shared mailboxes) moves its messages to Trash instead of removing them; without a Trash folder the request is refused with 409.
  - Writes in someone else's mailbox (shared or delegated) are audited (`mailbox.foreign.*`).
  - Let's Encrypt staging certificates never serve the mail protocols; assigning mail services to an expired certificate is refused (400).
  - Upload restores of backups run as a job (202) when called with `?mode=`; the pre-9.3 call with `?folderId=` keeps its synchronous answer.
- **New optional settings** (safe defaults): `BRANDING_NAME`, `BRANDING_COLOR`, `SCANNER_CHECK_INTERVAL_SEC`, `BACKUP_PGDUMP_TIMEOUT_MIN`, `BACKUP_UPLOAD_TIMEOUT_MIN`, `BACKUP_STALL_TIMEOUT_MIN`, `BACKUP_RESTORE_MAX_BYTES`, `BACKUP_RESTORE_MAX_MESSAGE_BYTES`, `BACKUP_RESTORE_MAX_FOLDERS`, `BACKUP_IMPORT_SYNC_TIMEOUT_MS`.

## Known limitations

- Contacts and calendar files inside ZIP backups are not restored yet.
- Restored messages get the restore time as their received time, so retention counts from the restore.
- Deleting a folder does not delete its subfolders; they are kept.
- The webmail still uses a horizontal app switcher and has no mail command bar; the OWA-style layout (left app rail, command bar) is planned.
