# CoreMail v8.0.0 — Protocol conformance, ActiveSync 14.1, local storage

**Image:** `magpeek/coremail-app:8.0.0` · **Helm chart:** 1.0.0 · **Date:** 2026-11-15 · **Predecessor:** v7.0.0

## Highlights

Every protocol was reviewed against its specification (RFC / open protocol specifications)
and Clean Code by independent reviewers; all critical, high and medium findings were fixed with
regression tests. An independent adversarial review of the whole release followed, and its
findings were fixed too. The release was tested end to end against the real container image
in both storage modes (MinIO 131/131, filesystem 126/126; 1,315 automated tests).

- **SMTP:** per-recipient relay results, verified smarthost TLS, `Received`/`Return-Path`,
  implicit MX, idempotent delivery, RFC 3464 bounces, stricter RFC 5321 syntax.
- **IMAP4rev2:** per-session sequence numbers with correct unsolicited updates, BINARY,
  SEARCHRES, LIST-EXTENDED/LIST-STATUS, modified UTF-7 names for IMAP4rev1 clients, ReDoS-safe
  LIST matching.
- **POP3:** atomic QUIT, maildrop lock, byte-exact sizes.
- **JMAP:** full sender policy, FUTURERELEASE, paged `/changes`, stable threads, WebSocket
  origin protection.
- **CalDAV/CardDAV:** REPORT filters, discovery (`/.well-known`), PROPPATCH, safe masking of
  private events, lossless vCard updates.
- **ActiveSync 14.1:** AirSyncBase bodies, ItemOperations, GetItemEstimate, Settings
  (out-of-office), Search, MoveItems, MeetingResponse, ResolveRecipients, mandatory device
  policy key and working remote wipe.
- **Storage:** local storage on a Docker volume (`OBJECT_STORAGE=filesystem`, default for new
  installs), S3 with TLS (AWS, B2, Wasabi, Hetzner, R2), `coremail storage migrate`.
- **Sessions:** credential changes take effect immediately everywhere — caches are invalidated
  and open IMAP/POP3/SMTP/ActiveSync/JMAP/SSE connections are closed; role changes end web
  sessions.
- **Kubernetes:** new Helm chart 1.0.0 (Pod Security "restricted", NetworkPolicies, Redis auth).

## Breaking changes — read before upgrading

The full list is in [CHANGELOG.md](../../CHANGELOG.md) → 8.0.0 → "Upgrade notes (breaking)".
The most important ones:

1. **Smarthost with a self-signed certificate** defers outbound mail until it has a valid
   certificate or `SMARTHOST_TLS_INSECURE=true` is set.
2. **ActiveSync** requires the device policy key on every command (standard phones re-provision
   automatically); deletes on the phone move mail to Deleted Items.
3. **SMTP** rejects non-conformant syntax (wrong keywords, unknown parameters, EHLO without a
   domain, malformed AUTH).
4. **POP3** needs Redis for logins; a second concurrent session of the same account gets
   `-ERR [IN-USE]`.
5. **Autodiscover** only answers for the caller's own addresses.
6. **Shared calendars:** grantees cannot edit or delete events they only see masked.
7. **JMAP:** mailbox delegates cannot send as the owner; `Email/set destroy` soft-deletes.
8. **Global address list** shows only the caller's own domain.
9. **Helm:** the old per-service chart is replaced — no in-place upgrade (see `infra/k8s/README.md`).
10. **Schema changes** are applied automatically at start — take a database backup first.

## Upgrade (Docker Compose)

```bash
cd /opt/coremail && docker compose pull && docker compose up -d
```

- Existing installations keep MinIO; no `.env` change is required. Moving to local storage is
  optional: `coremail storage migrate --from minio --to filesystem` (see `docs/storage.md`).
- Phones using ActiveSync re-provision once.

## Known limitations

- POP3: for messages stored before 6.0 without a raw copy, LIST can differ by 2 octets from
  RETR until the message is first downloaded.
- JMAP: `/changes` cannot tell "created" from "updated" for messages stored before 7.1 that are
  hard-deleted; affected clients do a full resync.
- CalDAV sync tokens have no tombstones; clients resync after deletions.
- IMAP and JMAP mailbox hierarchies are not unified.
- The Helm chart has not been tested on a real cluster yet (lint, template, kubeconform and a
  runtime test of the pod settings only).
