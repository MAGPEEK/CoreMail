# CoreMail v10.4.0: setup assistant — three-command deployment, automatic secrets, guided setup

**Image:** `magpeek/coremail-app:10.4.0` · **Helm chart:** 3.4.0 · **Date:** 2026-11-20 · **Predecessor:** v10.3.0

A minor release: existing installations upgrade without changes; additive schema only.

## Deploy in three commands

```bash
mkdir coremail && cd coremail
curl -fsSLO https://github.com/MAGPEEK/CoreMail/releases/latest/download/docker-compose.yml
docker compose up -d
```

Then open `http://<server>:3000/setup` and enter the token from `./secrets/setup-token`. Optional profiles: `--profile scanner` (spam and virus scanning), `--profile backup` (daily database dump), `--profile s3` (MinIO). Full guide: [docs/deploy.md](../deploy.md).

## Highlights

- **No required parameters.** All passwords and keys are generated into `./secrets/coremail.env` on the first start. Back up `./secrets/` — without it no password works after a restore.
- **Guided setup wizard:** domain and host name, administrator, a confirmed backup of the secrets, DNS records with a live check, certificate (Let's Encrypt, reverse proxy or later) and a summary with links.
- **No repository checkout needed:** PostgreSQL, rspamd and backup configuration ship in the image.
- **Every Compose variant and the Helm chart (3.4.0)** start without manually created secrets.

## Upgrade

```bash
cd /opt/coremail && git pull && docker compose pull && docker compose up -d
```

- Your `.env` keeps winning; its values are copied into `./secrets/coremail.env`. No new MFA, backup or Web Push keys are generated for existing installations.
- If you switch from the standard to the full Compose file and store mail in MinIO, set `OBJECT_STORAGE=minio` in `.env`.
